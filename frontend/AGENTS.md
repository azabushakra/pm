# Frontend Agent Guide (Planning Baseline)

## Scope

This document describes the current frontend code in `frontend/` before backend integration.

## Current Architecture

- Framework: Next.js App Router
- Language: TypeScript + React
- Styling: Tailwind CSS v4 with CSS variables in `src/app/globals.css`
- Drag-and-drop: `@dnd-kit/core`
- State model: local in-memory React state
- Data model: board/column/card types and helpers in `src/lib/kanban.ts`

## Entry Points

- App route `src/app/page.tsx` renders `KanbanBoard`.
- Global styles are in `src/app/globals.css`.
- Main board logic is in `src/components/KanbanBoard.tsx`.

## Current Board Behavior

- App shows a frontend-only login gate before board access.
- Demo credentials are `user` / `password`.
- Authenticated state is stored in `sessionStorage` for tab-session continuity.
- User can log out and return to the login screen.
- Board starts from `initialData` in `src/lib/kanban.ts`.
- User can rename column titles.
- User can add cards to a column.
- User can delete cards from a column.
- User can drag cards within and across columns.
- IDs for new cards are generated by `createId` helper.

## Component Map

- `AuthGate.tsx`: login gate, session auth state, and logout action.
- `KanbanBoard.tsx`: top-level board state and DnD wiring.
- `KanbanColumn.tsx`: column rendering + rename + add card controls.
- `KanbanCard.tsx`: card display and delete action.
- `KanbanCardPreview.tsx`: drag overlay preview.
- `NewCardForm.tsx`: inline card creation form.

## Testing Baseline

- Unit/integration tests: Vitest + Testing Library.
- E2E tests: Playwright.
- Existing test files:
  - `src/components/AuthGate.test.tsx`
  - `src/components/KanbanBoard.test.tsx`
  - `src/lib/kanban.test.ts`
  - `tests/kanban.spec.ts`
- Script commands from `package.json`:
  - `npm run test:unit`
  - `npm run test:e2e`
  - `npm run test:all`

## Constraints for Upcoming Work

- Keep MVP frontend simple.
- Preserve fixed column count/order; allow title edits only.
- Move persistence and AI behavior to backend endpoints when introduced.
- Avoid adding extra frontend-only features not required by the plan.

## Change Policy

- Treat this file as planning baseline.
- Update only when implementation reveals real, necessary deviations.
